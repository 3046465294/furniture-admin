# 至尊家居 · 现代化管理后台（v2.0 重构版）

把 2019 年那版 **RuoYi 4 + Spring Boot 2.1.1** 的「至尊家居智能管理系统」，用现在的主流技术**重写**了一遍——并且加上了第一版没有的**实时监控**能力。

> 这个项目是个人作品演示系统。**数据每 10 分钟自动重置为种子数据**，请勿填入任何真实个人信息。

---

## 为什么重写（面试可以直接讲的三个理由）

1. **老版本不能公开跑**：RuoYi 4 用的是 2019 年的依赖（Spring Boot 2.1.1 + 老 Shiro），有公开的 RCE 类漏洞史；把它暴露到公网，风险落在整台机器上。
2. **老版本没有可观测性**：出了问题只能翻日志文件。这一版从第一天就把**指标、日志、审计**做进服务里，有实时面板和 Prometheus 端点。
3. **零第三方依赖**：整站只用 Node 24 内置能力（`node:sqlite`、`node:crypto`、`node:http`）。**没有 npm 依赖 = 没有依赖链漏洞**，也就不需要天天升级补丁。

---

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 运行时 | **Node.js 24**（ESM） | 无构建步骤，`node src/server.js` 直接跑 |
| 数据库 | **`node:sqlite`（Node 内置）** | 零依赖；WAL 模式；预编译语句防注入 |
| 鉴权 | **scrypt + 自签 HMAC-SHA256 令牌 + 服务端会话表** | Cookie 里放的是会话 id 的 HMAC，库泄露也无法直接冒充 |
| 实时推送 | **SSE（Server-Sent Events）** | 每秒推一次指标 + 实时请求日志流 |
| 前端 | **原生 ES 模块 + 手写 CSS** | 无框架、无 CDN（CSP 只允许 `'self'`），深色主题、响应式 |
| 监控 | **自建指标聚合 + Prometheus 文本端点** | QPS / 错误率 / P50·P95·P99 / 慢接口 Top5 / 内存 / 会话 |

---

## 功能

**业务**：家具商品（增删改查、分页、搜索、分类筛选、上下架、**软删除**）、分类管理（分类下有商品会拒绝删除）、订单（状态流转、筛选）。

**监控（这一版的重点）**：
- 总览页实时卡片：QPS（10s 窗口）、P95 延迟、错误率（60s）、在线会话、RSS 内存、数据库体积
- 近 60 秒请求量折线（canvas 手写，不引图表库）
- 最慢接口 Top5（平均耗时 × 调用次数排序）
- **实时请求日志流**：每条请求的方法、路径、状态码、耗时、操作者
- 系统页：运行信息、各表行数、**操作审计**（谁在什么时候改了什么）、Prometheus 指标预览

## 安全设计（公开可用的前提）

| 风险 | 措施 |
|---|---|
| 弱口令 / 默认口令 | 无默认口令：首次启动生成 **16 位随机强密码**并只在控制台打印一次 |
| 暴力破解 | 按 **IP + 账号**双维度计数，连续失败 5 次锁定 10 分钟；锁定状态可在系统页查看 |
| 会话被盗 | Cookie 为 `HttpOnly` + `SameSite=Strict`；HTTPS 访问时追加 `Secure`；令牌带过期时间 |
| CSRF | 变更类接口强制要求 `X-Requested-With: fetch` 自定义头（跨站表单无法伪造） |
| XSS | 前端所有插值走 `esc()` 转义；响应头下发严格 CSP（不允许内联脚本、不允许外部资源） |
| 点击劫持 | `X-Frame-Options: DENY` + CSP `frame-ancestors 'none'` |
| SQL 注入 | 全部使用预编译参数，无字符串拼接 SQL |
| 越权 | RBAC：`admin` / `operator` / `viewer`，服务端逐接口校验，不依赖前端隐藏按钮 |
| 请求体攻击 | 请求体上限 256KB，超限直接 413 |

## 运行

```bash
# 依赖：只要 Node ≥ 22.5（本项目在 Node 24 上开发）
node scripts/seed.js          # 首次写入种子数据
node src/server.js            # 启动，默认 127.0.0.1:8090
```

首次启动会打印管理员账号与随机密码（**只打印一次**），例如：

```
[furniture-admin v2.0.0] 已启动 → http://127.0.0.1:8090/
  已创建管理员账号：admin
  初始密码（请立刻保存，页面不再显示）：xxxxxxxxxxxxxxxx
```

常用环境变量：`PORT` `HOST` `DB_FILE` `APP_SECRET`（会话签名密钥，生产必须设置）`ADMIN_PASSWORD`。

## 监控端点

| 端点 | 用途 |
|---|---|
| `GET /api/system/stream` | **SSE 实时流**：`metrics` 事件（每秒）+ `log` 事件（每次请求） |
| `GET /api/system/metrics` | 当前指标快照（JSON） |
| `GET /api/system/metrics.prom` | **Prometheus 文本格式**，可直接接 Grafana |
| `GET /api/system/health` | 健康检查 + 各表行数 + 会话数 |
| `GET /api/system/audit` | 操作审计（最近 50 条） |

## 与第一版的对照

| 维度 | 第一版（Geng 项目） | 这一版 |
|---|---|---|
| 框架 | RuoYi 4（Spring Boot 2.1.1） | Node 24 原生（无框架、无依赖） |
| 数据库 | MySQL + MyBatis XML | `node:sqlite` + 预编译语句 |
| 鉴权 | Shiro（含验证码） | scrypt + HMAC 令牌 + 会话表 + 登录锁定 |
| 视图 | Thymeleaf 服务端渲染 | 原生 ES 模块单页应用 |
| 可观测性 | 无（只有日志文件） | 实时指标 + SSE 日志流 + 审计表 + Prometheus |
| 部署 | 需要 JDK 8 + MySQL 常驻 | 单进程、零依赖、`node src/server.js` |

**能力是连续的**：第一版教会我「读懂框架的约定再动手」（审计字段、软删除、权限注解都沿用了下来），这一版让我把「安全边界」和「可观测性」补上。
