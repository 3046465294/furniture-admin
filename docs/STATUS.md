## 二、已上线能力

### 商城（前台）
- 首页楼层化：Hero / 服务承诺 / 分类磁贴 / 新品上架 / 热销推荐
- 商品列表：分类筛选、关键字搜索、排序、分页
- 商品详情：多图画廊（主图+缩略图）、**规格矩阵选择器**（联动价格/库存/SKU、缺货禁用、数量跟随库存）
- 购物车：规格级、实时库存校验、超卖拦截、抽屉式面板
- 结算：地址卡片单选、配送偏好、运费计算、金额拆分（商品/运费/应付）、防重复提交
- 订单：状态时间轴、物流信息位、金额明细、模拟支付（**演示环境，不接真实支付渠道**）
- 评价：仅可评价自己购买过的商品
- 体验：骨架屏、响应式、液态玻璃设计系统、PWA（可安装/离线壳）、无障碍（键盘+读屏+焦点环+减弱动效）
- 边界状态：404 友好提示、401 引导登录、网络失败可重试（防御性分支）

### 后台（运营）
- 商品 / 分类 / 订单 / 用户与 RBAC / 审计日志 / 告警规则（含低库存业务告警）
- **规格（SKU）管理**：列表、新增、改价改库存、停用（至少保留一个启用规格）
- **订单履约**：发货（快递公司+单号）/ 确认完成 / 退款（回补库存）
- 监控：Prometheus 指标端点 + SSE 实时流 + Grafana 看板
- 安全：全局安全响应头、JSON `no-store`、CSRF 校验、登录限流锁定、启动自检

### 交易与数据一致性
- 下单事务化：扣减规格库存 → 写订单与明细（**明细记录 `sku_id`**）→ 支付流水
- **未支付订单 15 分钟超时自动取消**并**按规格回补库存**
- 运费模板：地区命中 / 满额包邮 / 首件+续件
- 商品级库存恒等于「各启用规格之和」（前台展示、低库存告警同一口径）

### 可靠性
- **数据巡检**（用户级计划任务，每 2 分钟）：补默认规格 → 清理悬空购物车行 → 对齐商品级库存 → 补齐商品图
- **服务守护**（每 3 分钟）：服务掉线自动拉起
- **自研网关**：蓝绿加权 + 主动健康检查（连续失败摘除、恢复加回）+ 会话粘性 + **权重归零秒级回滚**（已实战使用过一次）

## 六、工程方法论（本项目实际执行的标准）

1. **端到端验收优先**：不看日志、不看代码，只看"线上点开能不能用"
2. **测量优于猜测**：每个结论都要有可复现的测量证据（本文档所有诊断均如此）
3. **故障注入验证自愈**：造出自愈机制要防的故障，再验证一次
4. **别名实例验证再上线**：改共享代码前先在备用端口起实例（曾因跳过这步导致商城中断 10 分钟）
5. **静态资源改动必升版本号**、**可缓存响应必须显式声明缓存策略**
6. **容错不要掩盖 bug**：后端兜底（如"未传规格就用默认规格"）曾让我晚一天发现前端根本没渲染规格
7. **数据模型演进时，唯一键/约束必须同步演进**（漏掉约束 = 改了一半）
8. **报告里"未通过"比"全绿"更有价值**：已知问题必须写根因与下一步，不粉饰
